# 添加中转站与切换模型

适用 `0.1.26-serial.4`，目标宿主为官方 DeepSeek Harness `0.2.2-rc.3`。本版复用 Harness 原生模型管理和开源适配器 `@deepseek-ai/dsh-llm-pi-ai`。增加中转站、改地址或换模型在原生设置中完成，无需修改小说代码。使用方式见 [长篇连载说明](使用说明.md)。

每章创建原生子会话并继承所选提供商和模型。模型只输出**正文与状态变更文本**，宿主检查、保存和记账；本流程不要求模型使用工具写文件，不需要另外配置文件工具或 Python。

## 添加提供商

1. 打开 **设置 → 模型 → 添加模型提供商 → 自定义模型 API**。
2. 填写稳定的小写 Provider ID，例如 `relay-a-openai`，再填写显示名称。会话与凭据会引用该 ID，换 ID 相当于新增提供商。
3. 按服务商说明填写 **基础 URL、API 协议、API 密钥**。
4. 在模型目录获取可用模型，或手动添加准确的模型 ID。显示名称可以自定义，请求 ID 必须与服务商一致。上下文窗口要容纳完整文风及前 10 章正文，最大输出要容纳本章正文和状态变更。
5. 保存，在写作主会话选择该提供商和模型。

密钥保存在 Harness 原生凭据中，不写入书稿、提示词或公开包。表单与字段参考 [Harness 官方模型配置指南](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/docs/user/guide/providers.zh.md)。

## 地址与协议

协议按服务商接口选择，不能仅根据模型品牌判断。下表为常见基础地址示例：

| API 协议 | 配置名 | 基础地址示例 |
| --- | --- | --- |
| OpenAI Chat Completions | `openai-completions` | `https://gateway.example/v1` |
| OpenAI Responses | `openai-responses` | `https://gateway.example/v1` |
| Anthropic Messages | `anthropic-messages` | `https://gateway.example` |
| Gemini API | `google-generative-ai` | `https://gateway.example/v1beta` |

填写 API 根地址，不填完整的 `/chat/completions`、`/responses`、`/v1/messages` 或 `:streamGenerateContent` 生成接口；以服务商对所选协议的说明为准。地址拼接及兼容选项参考 [官方适配器说明](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/llm/llm-pi-ai/README.zh.md)。

一个提供商对应一种协议。同站点有多种接口时分别添加提供商；多个中转站可并存，各自保存地址、凭据和模型目录。

## 先试写，再扩大批次

获取模型列表成功只证明该接口的认证与查询可用。先在单书「写作设置」选择「只试写 1 章」，检查模型是否完整返回正文与状态变更、宿主是否成功保存并记账，再启用 10／20／50 章或书库队列。

换线路前，先暂停并等待当前请求结束，在原主会话切换提供商和模型，再恢复原任务。新章节或修订使用新的原生子会话；已经发出的请求不在中途改线。插件不会因线路失败而静默换用另一付费线路或模型。

| 现象 | 处理方式 |
| --- | --- |
| 401、无效凭据 | 检查该提供商的密钥、权限和有效期。 |
| 403、`no_subscription` | 查看服务商返回原因，处理可用订阅或按量账户；模型目录可查询不代表生成账户已生效。 |
| 模型不存在、404 | 核对请求模型 ID、基础地址和协议。 |
| 429、配额或限流 | 核对余额、并发限制与服务商状态。 |
| 断网、超时、服务不可用 | 修复共同连接问题，再恢复原任务，不重复新建批次。 |
| 回复截断、正文或状态格式不完整 | 检查输出长度、模型能力及网关限制；查看检查结果和修订备份。 |
| 拒绝某个请求参数 | 参考服务商文档调整 Harness 原生兼容选项。 |

网络层重试由 Harness 管理。共享鉴权、计费或网络问题会暂停书库队列，不让后续每本书反复尝试同一错误。正文检查失败才进入有界自动修订；达到上限后等待作者明确重试。详见 [停止与恢复](使用说明.md)。

## 本版验证边界

最终包已通过四类原生协议与模拟 401 失败验证，准确核对模型路由、纯文本正文与状态返回、宿主保存；未调用模型工具，也没有静默换线。测试使用本地模拟网关，不能代替具体付费站点验收。详见 [验收记录](验收记录.md) 和 [中转协议收据](验收证据/relay-acceptance.json)。

历史上，`serial.2` 使用 AGI Plan 的 `gpt-6.1-terra` 进行过一次真实请求：模型目录认证成功，生成请求因 **403 `no_subscription`** 受阻，没有正文产出。这是旧版和当时账户状态的记录，不代表本版已完成真实付费写作测试。
