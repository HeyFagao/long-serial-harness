# 长篇连载使用说明

适用 `0.1.26-serial.11`，宿主为官方 **DeepSeek Harness 0.2.2-rc.3**。先看 [快速开始](先看这里.md)，测试范围见 [验收记录](验收记录.md)。

## 安装与模型

推荐直接在 Harness「插件 → 添加插件 → 包名或地址」粘贴公开 `.tgz` 安装直链，见 [GitHub 安装说明](GitHub安装说明.md)。

本地安装时将本包完整解压，保留 `.tgz` 与安装脚本在同一目录。

- **macOS**：运行 `install-serial.command`，使用官方应用自带的 CLI。
- **Windows**：先在 Harness 菜单「管理 dsh 命令 / Manage dsh Command」安装或修复命令，再在 PowerShell 中运行 `./install-serial.ps1`。

也可手动安装：

```sh
dsh plugin --profile desktop add './oh-story-dsh-0.1.26-serial.11.tgz'
```

保存当前工作后重新打开 Harness，确认工作台顶部的运行版本为 `0.1.26-serial.11`。安装只更新该 profile 的 `@oh-story/dsh`，保留其他插件和模型设置；脚本不自动关闭应用。已运行的旧进程需要重开后才加载新版。日常使用不需要单独安装 Node.js、pnpm 或 Python。安装依赖需要能访问 Harness 使用的 npm 源。

在 Harness 原生设置添加中转站与模型，详见 [中转站设置](中转站设置.md)。换站点或模型不需要改小说代码。

## 本批写作模型与思考强度

单书和书库的启动区域都有「写作模型」「思考强度」及「刷新模型列表」。先选模型和适用的强度，再启动试写、10／20／50 章或全本；书库勾选批量生成同样适用。模型按 Harness 已配置的提供商分组，可选择其中可用的文本模型，不按 GPT、Claude、Gemini 等品牌限制。尚未出现的模型先在 Harness「设置 → 模型」添加，再点「刷新模型列表」。刷新列表只读取配置，不发起写作请求。

初次打开默认带入当前会话的提供商、模型与思考强度，可自行改选；按生成设置界面显示的模型与强度启动并保存，之后切换聊天模型不会改变这批。「刷新模型列表」读取最新目录和原生会话配置，不会静默覆盖已选模型；要重新带入原生会话最新选择，先刷新列表，再选「使用当前会话配置」。手动选模型时，「思考强度」只显示宿主为该具体模型提供的选项，以及「模型默认」；不同模型的选项可能不同。选择「模型默认」由宿主解析该模型的默认设置；目录没有提供可调强度时不能手动调节，使用模型默认。

启动时，本批模型与强度会随任务保存，正文、修订和独立标题都使用该选择。进度中可查看本批保存的设置。暂停、停止后恢复和重试沿用原批选择；更改下拉框只影响接下来启动的新批次。书库运行中追加其他书时可以选择另一模型，原来那些书继续用各自的原设置。选择器不会修改 Harness 主会话模型、中转站地址或密钥。

## 导入书项目

1. 在 Harness 添加专用书库文件夹，打开会话。
2. 在「小说书库」点击「批量选择 TXT / Markdown」。一份最终输出对应一本书；书名可填写，也可留空识别。
3. 「导入到文件夹」默认是「新批次（自动新建）」。可填「本批文件夹名称」，也可留空由书库顺次命名为「第一批」「第二批」。给已有批次补书时，在下拉框中选那个文件夹。
4. 确认导入后，在相应文件夹中查看书名和进度。每本书有独立目录与 Harness 工作区，点「打开」进入。
5. 若文件已经保存但工作区登记失败，点击「重试登记项目」，不用再次导入。

每个书库从 001 开始保存固定编号。同一批文件按文件名自然排序，例如 `1.txt`、`2.txt`、`10.txt`。新书领取下一个书号，即使导入已有文件夹也是如此。重复导入同一本书保留原编号，包括删除后重新导入相同内容与书名的书；这只会重新建立项目，不会恢复已删除的正文。删除不会使其他书重排，旧号不分配给其他书，新书继续末尾编号。搜索、筛选和选择部分书不会改变编号。旧书库按此前显示顺序建立初始编号，首次导入、导出或删除等操作时固定保存；旧版没有可靠原始导入顺序时，不推断或恢复原导入时间。编号只用于书库展示与导出，不改原书名、项目目录或正文。

一次最多 50 本，单份最多 2 MB，合计最多 32 MB，超出时分批。支持原 `&&&区段名&&&` 格式、常见 Markdown 标题和中文数字章号。七区最终输出可整份导入，保留原文、拆出章纲并识别核心设定中内嵌的完整文风；不用手动拆成数百个文件。格式可参考包内 `大纲格式示例.txt`。

## 用文件夹整理新旧批次

首次打开升级后的旧书库，旧版没有保存批次的书集中在「未分组」。知道哪些书属于同一批时，可点「新建文件夹」并命名，再勾选这些书，在「将所选书移至」中选目的地，点「移动所选书」。已归档的书也可以这样调整。文件夹管理的是书库中的归属，整理时可以继续沿用原项目路径和生成进度。

书库按文件夹创建先后显示，「未分组」在前。可收起已处理的文件夹。用顶部「跳到文件夹」定位最近的批次，用「只选本批」集中生成或导出一组。要同时处理几批，可以勾选各文件夹的「全选本批」。文件夹移空后可点「删除空文件夹」。要更换文件夹名称，点该组旁的「重命名」。再次导入已存在的同一本书时，它保留在原文件夹。

「整理顺序」支持在同一文件夹中拖动书卡或用「上移」「下移」调整。点击「完成整理」退出。「恢复导入顺序」按固定书号恢复组内顺序。调整书卡和文件夹归属后，导出的书包继续使用原固定书号。

勾选同一文件夹的书导出，总包会带上文件夹名，例如 `第二批_小说正文_TXT合集.zip`。跨文件夹导出时，可在总包的「导出说明.txt」核对每本已导出书的归属。

Harness 左侧工作区以「文件夹 · 书号 · 书名」显示，同组的书相邻。需要折叠整个文件夹或批量整理时，打开书库工作台。出现同步提示时可点「重试同步」。

## 单书生成

选择 **10／20／50 章／全本**。首次使用先在「写作设置」选择「只试写 1 章」并检查。全本以导入大纲末章为终点，200 章、400 章等长度都从实际大纲确定。

默认建议每章 2300—2500 字，可调整写作参考目标。硬性字数验收仅要求正文超过1500字，不设上限，2524字不会因超过2500字退回。原提示词与文风原件保留，附加的当前规则优先。

每章使用全新的原生子会话，使用本批保存的提供商、模型和思考强度，并继承宿主权限，实际带入**完整文风与此前最多 10 章正文全文**，不足时使用已有前章。当前章纲及人物、伏笔等状态一并提供；修订也保留所需上下文。模型只返回正文与状态变更，由宿主分离、检查、保存和记账，不需要模型操作文件。

## 暂停、停止与重试

| 操作 | 行为 |
| --- | --- |
| 本章后暂停 | 当前章保存并检查后暂停，不再派发下一章。 |
| 立即停止 | 请求取消当前写作，保留进度、现稿和备份。 |
| 恢复这批 | 恢复已停止的原批次，先检查现稿，再继续或修订。 |
| 继续本批／重试并继续 | 恢复暂停或受阻任务，重新核对已保存进度。 |

正常返回但检查失败时，宿主先备份，再自动修订当前章，**首次失败后自动重试 5 次**。仍不过就等待作者处理；明确点击「重试并继续」才追加有限尝试窗口，累计次数、原任务身份和备份都保留。模型失败自动重试最多5次；用户主动暂停、停止或权限审批不会被自动重试绕过。文件被手动修改或保存冲突时保留原稿并提示处理。

停止后若有未验收稿，使用「恢复这批」，不要另开批次覆盖。任务属于另一会话时，点击「回到任务会话」。发现已验收文件被修改时会停批并保留现场，不自动回滚作者编辑。

## 选书与批量生成

书库总览按整页展示书单。先勾选要更新的书，再选择每本 **新增 10／20／50 章／写至完本**。默认范围为「所选书籍」，未勾选不会启动；按钮显示本次书数与章数。需要全库操作时，明确切换到「全部可新增的书」；正在写、单独暂停、待处理和已完本的书保持原状态。

可搜索书名、全选搜索结果，或用「选择可新增」「选择已完本」快速勾选。搜索不会取消其他已勾选的书，界面会提示搜索结果之外仍被选中的数量。导出、删除也使用当前勾选结果。

书间默认「同时生成（不限并发）」，也可自定义任意正整数；同一本书始终逐章生成，各书文风、前文、状态与执行位置独立。新书可以加入正在运行的队列，不必等待其他书写完；本次加入时的并发设置用于后续调度，不会重置已有书的进度或目标。新加入书使用本次开始时选择的模型与思考强度，已有书保持各自原批设置。

勾选书后点击「暂停所选书」：排队中的书不再开始，正在写的书完成并保存当前章后暂停，其他书继续。点击「继续所选书」沿用原批目标、模型和思考强度，不额外增加章数；例如原目标为第 20 章，写到第 8 章暂停后继续，仍写到第 20 章。已有未完成批次的书不能直接改成新的新增章数，先继续原批。

每行也有适用的「暂停」「继续」按钮。全局「本章后暂停所有项目」「停止所有项目」控制整批；全局继续不会擅自恢复此前单独暂停的书，需勾选那些书再继续。单书内容错误记录后其他书继续；鉴权、订阅／余额、网络等共享错误会暂停整队，修复共同原因后再继续。

## 独立生成公众号标题

每章正文先用原提示词写作并验收落盘；随后新建独立原生会话，只发送本章完整正文、书名、章号和标题提示词。它与正文使用同一批次保存的中转站、模型和思考强度。全书大纲、前十章、文风和写作指令只属于正文阶段，不会混进标题调用。

本版使用作者提供的标题提示词：优先从本章前 800 字抓开场钩子，再看前 2000 字补足关系与后果期待，其余本章正文只用于核实事实。模型拟 5 个不同角度的候选并给出前三推荐，系统保存全部候选，导出时放在每章 TXT 开头供作者选择；文件名继续使用第一推荐。每个标题为 15—25 个可见字符，标点、数字计数，空格和外层书名号不计；超限重新拟题，不截断。

标题、原文依据、候选、简短核心爆点、标题策略与番茄标签单独保存到 `追踪/公众号标题/`。五个候选按 1—5 编号进入导出的 TXT 开头，供发布时自行选择；策略、标签和依据只存内部记录，也不改变原书名。更新后新发起的标题调用使用新提示词，已有标题不会自动重做，`正文/` 原稿不改写。标题失败最多自动重试5次，仍失败后提示处理；「重试并继续」只补标题。暂停在标题阶段会显示“正文已保存，标题已暂停”，继续也只补标题。完成标题后再进入下一章。通常每章至少2次模型调用，正文或标题重试会额外增加调用和用量。

打开已完成章节的预览，可在「公众号备选标题」中查看与该章正文对应的候选。正文文件中的原短章名与公众号标题分别保留，导出会在 TXT 开头列候选。旧章只有短章名或单个旧标题时，沿用已有内容；新版续写的新章必须生成五个 15—25 字候选。升级时未结束的旧标题调用若仍返回单个标题，只重试标题，不重写已保存正文。

调研与方法见 [公众号小说标题调研](公众号小说标题调研.md)，完整提示词见 [公众号小说标题提示词](公众号小说标题提示词.md)。程序会核对标题依据确实存在，但不能代替对标题吸引力、语义和实际传播效果的人工判断。

## 批量导出与整理

在书库总览勾选书籍，也可以「全选书项目」或「选择已完本」，再点击「批量导出 TXT」。**每章一个TXT，每本书一个ZIP；勾选多本时再装入一个总ZIP下载。** 每章 TXT 开头按 1—5 编号列出全部已保存候选标题，其后为书名、章号和正文，不混入大纲、提示词、策略、标签、状态变更或运行日志。TXT 文件名沿用第一推荐；旧记录只有一个标题时只列出该标题，导出不额外调用模型。书籍 ZIP 前缀使用书库固定编号，与卡片一致；仅勾选部分书也保留原号，不从 001 重新排序。下例只选了编号 001 与 004 的书：

```text
小说正文_TXT合集.zip
├── 001_第一本书_全本.zip
│   ├── 第001章_本章公众号标题.txt
│   ├── 第002章_本章公众号标题.txt
│   └── 目录与导出说明.txt
├── 004_另一本书_未完结_已保存10章.zip
│   ├── 第001章_本章公众号标题.txt
│   └── ...
└── 导出说明.txt
```

单书面板「导出章节 TXT 压缩包」直接下载该书ZIP。TXT使用带BOM的UTF-8与Windows换行。书包使用书库固定编号，章节文件带章号，同名书或重复标题不会互相覆盖。

导出时正文会做手机阅读排版：段落之间空一行，口语对白单独成段，过长的叙述在句号、问号或感叹号处断开。不改故事用词、人名和情节，也不改写书库里的原稿；已经写好的章节在下次导出时同样排版。书名、章号、备选标题和单独保存的状态变更保持原样。

未完结的书可导出当前已完成章节，包名注明章数。正文已保存但标题仍待完成的当前章暂不进入导出。无可导出正文或校验失败的书会跳过并列入总包说明；全都不能导出时直接提示，不下载空包。旧稿未生成独立公众号标题时沿用其原章节名，导出不会调用模型。单本正文最大64MB，单批合计128MB，超过时分批选择。

勾选书后点击「删除所选书」，**立即从列表移除，不再二次确认，也不用先停止生成**。正在生成、排队、失败、暂停或已完本的书都可选中删除。后台保存删除请求，停止这些书的正文或标题调用，并从批量生成队列中移除；其他书继续运行。

后台随后永久清理所选书的项目目录，包括导入副本、设定、文风、大纲、正文、标题、进度、修订备份和错误文件。遇到文件占用等暂时问题会自动重试，书不会重新出现在书库，也不弹出清理错误；重新打开书库后继续未完成的清理。外部原始输入文件、其他书和模型设置保留。删除后的书不能恢复；需要保留成稿时先导出。写完或导出都不会自动删书。

旧版本回收站中的书仍可勾选导出或永久删除，不再提供恢复入口。对应 Harness 工作区入口会移除；Harness 自身保存的历史会话由宿主管理，本功能不承诺清除其会话历史。

## 保存与运行

保持 Harness 后台常驻、电脑唤醒和网络可用。关闭页面不停止宿主调度；退出应用后，重新打开原书库／作品及所属会话，再恢复任务。日常杂事可在其他 Harness 会话处理。

日常选书、生成、导出和删除集中在书库主区域，书单没有独立的嵌套滚动区。「查看运行记录」默认折叠，其中任务与追踪记录只读；无需编辑这些技术文件。正文、大纲和设定仍可在单书项目预览、编辑。

备份整个书库时，复制书库根目录，连同其中的「追踪」和所有小说项目一起保存，书籍编号、文件夹归属和排序都在书库内。要单独备份一本书，复制该书完整项目目录，其中包括原文、设定、大纲、正文和追踪记录。批次状态在 `追踪/连载任务.json`，修订备份在 `追踪/连载修订/`；导出只汇总已完成正文。不要重新导入来恢复原任务。

恢复任务保留原批模型与思考强度；要使用另一模型，在新批次开始前选择。处理同一提供商的地址或密钥问题时，先暂停并等待当前请求结束，再到 Harness 原生设置修复并恢复原批。成稿的情节、文风和质量仍需人工检查。源码构建和许可见 [来源说明](来源说明.md)。
